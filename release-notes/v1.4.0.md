# Python Data Intelligence SDK 1.4.0 Release Notes

## Python SDK for Data Intelligence

| **Version:** |1.4.0|
|--------------|-----|
| **Revision:** | <Put release date> |

## What's New

### Models

- Added `DIClient.get_all_models()` and `DIClient.get_model(name=...)` to list and describe all models
  (embedding models and LLMs). These endpoints no longer require authorization, so they are available on
  `DIClient` and not only on `DIAdminClient`.
- Generalized the model data object `V1ModelsResponse` with additional attributes: `communicationType`,
  `contextLength`, `temperature`, `topK`, `topP`, `timeout`, `language`, `sampleRate`, `automaticPunctuation`
  and `endpoint` (custom-function endpoint URL).
- Extended `ModelTags` with `Image-Text-To-Text`, `Automatic-Speech-Recognition`, `Video-To-Text` and
  `Custom-Function` capabilities so models can be filtered by use case.

### Pipelines

- Added support for Nvidia AIDP transcribe workflows: `create_pipeline()` accepts `prompt` for
  `transcribe-metadata` pipelines (audio, image and video transcription).
- Added support for NIM RAG chunking: `create_pipeline()` accepts `chunk_size` and `chunk_overlap` for
  `rag` pipelines.
- Added support for `custom-function` pipelines, including validation that `model` and `schema` are supplied.
- `schema` is now a mandatory argument of `create_pipeline()`.
- `event_filter_max_object_size` is now optional.

### Collections

- Added `output_store` to `create_collection()` to route transcription output to a destination bucket.
- Added `indexing_mode` to `create_collection()` for RAG collections (`HNSW`, `GPU_CAGRA`). When omitted, the
  indexing mode is auto-detected.

### Schemas

- Added `DIAdminClient.create_schema()` and `DIAdminClient.delete_schema()`.
- `SchemaItem` supports a `nullable` flag (defaults to `True`). Fields marked `nullable=False` are created as
  `NOT NULL` columns and validated strictly.
- Refactored schema data models into typed responses (`V1SchemasResponse`, `V1ListSchemasResponse`,
  `V1CreateSchemaResponse`, `V1DeleteSchemaResponse`) with alias-safe mapping of the `schema` field.

### Error handling

- Added `PipelineValidationError`, raised for both client-side and server-side (HTTP 422) pipeline validation
  failures. The exception exposes `errors`, `source` (`"client"` or `"server"`), `status_code` and
  `raw_response`, and renders a single readable message listing every invalid or missing field.
- Missing or unexpected arguments passed to `create_pipeline()` are reported as `PipelineValidationError`
  instead of a bare `TypeError`.

### Documentation and packaging

- Documentation site migrated to the HPE theme.
- The package is published to PyPI and can be installed with `pip install pydi-client`.

## Deprecations

| Deprecated | Replacement |
|------------|-------------|
| `DIAdminClient.get_embedding_model(name=...)` | `DIClient.get_model(name=...)` |
| `DIAdminClient.get_all_embedding_models()` | `DIClient.get_all_models()` |

Both deprecated methods emit a `DeprecationWarning` and will be removed in a future release.

## Resolved Issues

- Collection and pipeline APIs no longer log `created successfully` when the underlying request fails.
- Pipeline and schema request payloads serialize the `schema` field correctly instead of dropping it because
  of the Pydantic alias collision with `BaseModel.schema`.

## Known Issues

- Creating new models is not supported. Use the models available in the deployment.
- Structured Query support is limited.
